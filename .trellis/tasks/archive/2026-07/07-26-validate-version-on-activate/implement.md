# 实施计划

1. 读取两仓库相关 Trellis 后端规范。
2. 在 cdk-server 中将最低版本提升为 `2.5.3`，为租户激活增加带版本请求契约，并在副作用前校验。
3. 补充服务端缺失、非法、过低和受支持版本测试，更新 API 文档。
4. 在 SkinForge 中将包版本提升到 `2.5.3`，并让激活请求携带编译版本。
5. 运行 cdk-server 格式化、检查和测试；运行 SkinForge Rust 格式化与检查/测试。
6. 检查跨仓库 diff，确认通用激活接口与旧 CLI 未改变。

## 风险点

- 不应复用并扩展现有 `ActivateRequest`，否则会意外破坏非 SkinForge 激活入口。
- 校验必须发生在租户查找和数据库写入之前。
- SkinForge 的 Cargo 清单和锁文件版本需要保持一致。
