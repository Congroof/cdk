# 优化多设备 CDK 查询

## 目标

收紧“多设备 CDK”列表的查询结果，优先呈现换绑行为相对历史机器数量更异常的 CDK，减少无效结果。

## 已确认事实

- 现有接口为 `GET /api/cdk/multi-device-bindings`，前端页面为“多设备 CDK”。
- 当前结果必须同时满足：成功绑定历史涉及至少 2 台不同机器，且成功换绑次数至少 6 次（严格大于 5）。
- `machine_count` 是成功绑定历史中非空 `old_machine_code` 与 `new_machine_code` 的去重并集；前端列名显示为“历史机器”，其中也包含当前机器。
- `rebind_count` 只统计 `event_type = 'rebind'` 的事务提交成功记录，不包含失败验证、定时校验或普通验证。
- 文本搜索匹配 CDK、当前机器码以及绑定历史中的旧/新机器码；查询、聚合和分页都按当前用户隔离。
- 用户希望结果进一步限定为“换绑次数大于历史机器”。

## 需求

- 保留现有 `rebind_count > 5` 门槛，并新增聚合条件：`rebind_count > machine_count`；两个条件必须同时满足。
- 计数查询与数据查询必须应用完全相同的条件，保证分页总数准确。
- 页面说明和 API 文档同步描述新规则。
- 保持现有租户隔离、文本搜索、分页和稳定排序行为。

## 验收标准

- `rebind_count <= machine_count` 的 CDK 不出现在列表中，也不计入分页总数。
- `rebind_count > machine_count` 且满足其余既有条件的 CDK 正常返回。
- 等于边界不返回，例如换绑 6 次、历史机器 6 台时不返回。
- 后端测试覆盖 SQL 中的跨聚合比较条件及既有参数绑定数量。
- 前端说明文字与 API 文档和实际查询规则一致。
- 后端测试、格式检查及前端 lint/build 通过。

## 范围外

- 不改变绑定历史的写入规则或统计口径。
- 不新增数据库字段或迁移。
- 不改变文本搜索可匹配的字段。
- 不改变列表返回字段或绑定详情接口。

## 已确认决策

- 新条件叠加在现有“换绑次数严格大于 5”的门槛之上，不替代固定门槛。
