# 自定义 MOD 分类管理生产回归审计

## 目标与用户价值

对 `00a77ca` 起新增的自定义 MOD 分类管理及后续修复做一次生产级复盘，找出静态构建和现有单元测试未覆盖的运行时缺陷，修复已确认问题，并建立能够覆盖数据库真实类型、HTTP 契约、异常降级和前端关键交互的回归验证，避免继续以生产环境作为测试环境。

## 已确认事实

- 功能主提交为 `00a77ca feat: 增加自定义 MOD 分类管理`，后续包含临时链接、预览图和两次数据库类型修复。
- 生产暴露过两类 MySQL 运行时解码问题：预览列存在性检查和 MOD 列表 `COUNT(*)` 的 Rust 接收类型不匹配；它们都通过了原有编译与单元测试。
- 当前 `cargo test` 40 项通过、前端 ESLint 通过、前端 production build 通过。
- `cargo clippy --all-targets --all-features -- -D warnings` 被两个与 MOD 无关的历史未使用模型阻断，不能据此证明 MOD 功能失败，也不能忽略这项质量门禁。
- 当前 MOD 测试集中在纯函数，缺少真实 MySQL schema/查询解码、路由响应契约和管理端关键流程的回归覆盖。
- 当前工作树在审计开始前干净。

## 审计与修复范围

1. 审查 `00a77ca^..HEAD` 内与 MOD 相关的数据库、后端模型/处理器、KDocs、路由、前端、文档和部署 schema。
2. 重点验证：
   - 新库初始化与旧库升级路径；
   - MySQL `BIGINT UNSIGNED`、`COUNT(*)`、可空列的真实 SQLx 解码；
   - 分类筛选、分页、稳定排序、重复导入、删除和下载查询；
   - 公开字段白名单、分页字段命名和 `Cache-Control`；
   - 预览图批量换链失败/超时的降级；
   - JSON 边界、数据库列长度、整数精度和错误状态映射；
   - 前端分类切换、导入、删除末页回退、加载竞态和错误展示；
   - 三份 schema 的一致性及现有 release/hash 路径不回归。
3. 对审计中确认的问题直接修复，并为每个生产级根因补回归测试或自动化检查。
4. 不改变已发布的 MOD 产品语义，不扩展分类、描述、版本或安装功能。

## 验收标准

- 后端格式化、单元测试和 MOD 相关 Clippy 检查通过；全量严格 Clippy 的历史阻断被明确隔离或一并清理后通过。
- 前端 lint、TypeScript 检查和 production build 通过。
- 在真实 MySQL 8 上验证全新 schema 与从无 `preview_file_id` 的旧 schema 升级均能启动。
- 在真实 MySQL 8 上覆盖 MOD 列表有/无分类的计数与行解码、插入、重复约束、删除、分页边界。
- HTTP/序列化契约测试覆盖公开字段白名单、分页字段和 `no-store`。
- 输入边界不会因数据库截断或数字精度问题变成未说明的 500；错误状态与文档一致。
- 预览图服务失败不影响列表，下载换链失败按 503 返回。
- 代码、API 文档、TypeScript 类型、迁移、启动建表和 Docker 初始化 schema 保持一致。
- 最终报告列出：发现的问题、根因、修改、执行过的命令及结果、仍需依赖真实 KDocs/生产配置验证的外部边界。

## 非目标

- 访问或修改生产数据库、生产 Cookie、真实 MOD 文件。
- 重构与 MOD 无关的业务模块。
- 对第三方 KDocs 服务可用性作绝对保证。

## 开放问题

无。用户已明确要求立即对最近的自定义 MOD 相关提交做全面审核、测试并修复，范围与风险偏好足以进入执行。
