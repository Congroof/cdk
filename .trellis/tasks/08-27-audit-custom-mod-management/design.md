# 自定义 MOD 分类管理生产回归审计设计

## 审计策略

采用“提交差异 → 跨层契约 → 真实数据库 → 故障路径 → 全量门禁”的顺序。编译通过只证明静态类型成立；本次必须用 MySQL 8 执行真实 SQL，覆盖 SQLx 在运行时才会发现的数据库类型兼容问题。

## 测试分层

1. **纯函数/序列化测试**：清单边界、分页、公开 DTO、响应头和错误映射。
2. **MySQL 集成测试**：独立测试数据库验证建表/升级、插入、计数、筛选、分页、唯一约束和删除。
3. **路由契约测试**：尽量通过 Axum 路由调用覆盖 JSON envelope、字段命名、鉴权边界与状态码；外部 KDocs 调用以可测试边界或失败降级验证。
4. **前端静态与交互逻辑**：把 JSON 守卫和分页状态等关键逻辑提取为可测试单元，至少由 TypeScript、ESLint 和 production build 兜底；若项目没有前端测试框架，不为本次引入大型框架，优先减少组件内不可测逻辑。
5. **部署验证**：Docker MySQL 8 同时验证全新初始化 SQL 和旧表升级路径。

## 兼容与风险控制

- 不访问生产数据；使用隔离数据库和占位 KDocs 凭证。
- 不持久化临时 URL，不扩大公开字段。
- 对外 JSON 契约如需纠正，优先保持既有已文档化字段兼容，避免客户端二次故障。
- 所有 schema 变更保持幂等，旧库升级失败必须在启动阶段显式暴露。
- 外部 KDocs 成功路径无法由本地伪造真实服务保证；本地验证请求构造、超时、错误映射和降级，真实凭证 smoke test 单独列为上线前检查。

## 完成证据

最终以命令输出、测试名、MySQL schema 查询结果和 git diff 为证据，不以“代码看起来没问题”作为结论。
